# Выпуск обновления

Одна команда, один способ. Раньше релизы собирались восемью разными скриптами,
файлы переименовывались руками — из-за этого автообновление ломалось. Всё
старое лежит в `_archive/release-scripts/` и больше не используется.

## Разовая подготовка

Нужен GitHub Personal Access Token с правом `repo`:
https://github.com/settings/tokens → Generate new token (classic).

Токен передаётся сборщику через переменную окружения `GH_TOKEN`.

## Выпуск новой версии

1. Поднять версию в `package.json` (поле `version`, например `1.0.14` → `1.0.15`).

2. Переписать `RELEASE_NOTES.md` — его содержимое становится описанием
   релиза на GitHub и показывается в окне обновления внутри приложения.
   Формат обязателен: разделы `## 🇷🇺 Что нового` и `## 🇬🇧 What's new`,
   пункты списком через `-`. Приложение выбирает раздел под язык
   интерфейса; без этих заголовков покажется первый попавшийся.

3. Запустить публикацию. Самый простой способ — правый клик по
   `publish.ps1` и «Выполнить с помощью PowerShell». Скрипт сам возьмёт
   токен из `fix-release.ps1`, соберёт установщик и загрузит его.

   Либо вручную, если токен хранится где-то ещё:

```bash
$env:GH_TOKEN = "ваш_токен"; npm run release
```

Всё остальное делает `electron-builder`: собирает установщик, считает
контрольные суммы, создаёт черновик релиза на GitHub и загружает в него
три файла.

4. Открыть https://github.com/Agrysif/WatchTwitch/releases, проверить
   черновик и нажать **Publish release**. Пока релиз в черновиках,
   установленные копии приложения его не увидят.

## Что должно оказаться в релизе

Ровно три файла:

| Файл | Зачем |
|---|---|
| `WatchTwitch-Setup-X.Y.Z.exe` | сам установщик |
| `WatchTwitch-Setup-X.Y.Z.exe.blockmap` | докачка только изменившихся кусков |
| `latest.yml` | **описание обновления — без него ничего не обновится** |

Если `latest.yml` в релизе нет, старые версии просто не узнают о новой.
Именно это происходило раньше: скрипты загружали exe и blockmap, а `latest.yml`
не загружали вовсе.

## Главное правило

**Имя файла внутри `latest.yml` обязано совпадать с именем файла в релизе — символ в символ.**

Приложение читает `latest.yml`, берёт оттуда имя и скачивает файл по нему.
Не совпало — тихий отказ без сообщения об ошибке.

Раньше сборщик создавал `WatchTwitch Setup 1.0.12.exe` с пробелами. GitHub при
загрузке заменяет пробелы точками — файл становился `WatchTwitch.Setup.1.0.12.exe`,
а в `latest.yml` оставалось `WatchTwitch+Setup+1.0.12.exe`. Обновление отваливалось.

Сейчас в `package.json` задано `nsis.artifactName`, которое даёт имена через
дефисы — пробелов нет, подменять нечего. **Это поле трогать нельзя.**

## Проверка после выпуска

```bash
curl -s https://api.github.com/repos/Agrysif/WatchTwitch/releases/latest | grep '"name"'
```

В списке должны быть все три файла. Затем — прочитать сам `latest.yml`:

```bash
curl -sL https://github.com/Agrysif/WatchTwitch/releases/latest/download/latest.yml
```

Имя в поле `url` должно точно совпадать с именем `.exe` из списка выше.

## Если обновление не приходит

Проверять по порядку:

1. Релиз опубликован, а не висит черновиком (`draft: false`).
2. Релиз не помечен pre-release — приложение берёт только обычные релизы.
3. `latest.yml` присутствует в файлах релиза.
4. Имя в `latest.yml` совпадает с именем загруженного `.exe`.
5. Версия в релизе больше установленной.

Логи обновления видны при запуске из консоли (`npm start`), строки с префиксом
`[Updater]`.

## Откат

Удалить или пометить как pre-release проблемный релиз на GitHub — приложения
снова начнут видеть предыдущую версию как последнюю. Уже обновившиеся копии
сами не откатятся: `allowDowngrade` выключен намеренно.
