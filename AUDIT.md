# Проверка WatchTwitch 1.0.22 — 26 сентября 2026

Обновление: ошибки ниже исправлены в патче 1.0.23. Это исходные результаты аудита 1.0.22; актуальные проверки патча приведены в конце документа.

Проверен текущий исходный код, прочитаны README.md и RELEASE.md. Выполнен npm test: 299 проверок, 0 ошибок. Дополнительные сценарии ниже выявляют ошибки, которые штатный набор не покрывает.

Границы проверки: уведомления проверены в настоящем Electron из node_modules, с отдельным временным профилем. Логика фарминга проверена исполнением исходных методов в Node VM с управляемыми ответами API и таймерами. Реальный аккаунт Twitch, получение настоящей награды и длительный онлайн-фарминг не проверялись. Полный интерфейс приложения вручную не проходился. Производственный код не изменён, релиз не выпускался: запрос был на диагностику и результат.

## 1. Высокий приоритет: уведомление остаётся навсегда

Место: main.js:2451–2568, renderer/notification.html.

Шаги: показать уведомление; через 600 мс показать следующее; дождаться автоматического закрытия; попытаться закрыть второе вручную.

Реальный результат Electron:

```text
AUDIT single notification remaining windows: 0
AUDIT replacement: {"oldDestroyed":true,"newDestroyed":false,"currentReferenceLost":true}
AUDIT after timeout: {"remainingWindows":1,"newDestroyed":false,"currentReferenceLost":true}
AUDIT after manual close: {"newDestroyed":false}
```

Обработчик closed старого окна безусловно присваивает глобальной переменной dropNotificationWindow значение null. К этому времени она уже указывает на новое окно. IPC-закрытие использует эту переменную, поэтому второе окно невозможно закрыть ни по таймеру, ни кликом. Тест после проверки принудительно уничтожает свои окна.

Исправление: обнулять ссылку только если закрывается именно текущее окно; закрывать окно отправителя IPC; добавить резервный таймер в главном процессе.

## 2. Высокий приоритет: приоритет подписок обходит ограничения кампании

Место: renderer/js/pages/farming-page.js:1734–1787.

В кампании разрешён канал allowed, он присутствует в выдаче. В избранном есть favorite, ведущий ту же игру, но не разрешённый кампанией. При включённом приоритете подписок pickPreferredStream возвращает favorite. Фильтр allowed применяется к исходной выдаче, но последующий прямой поиск подписок его обходит.

Результат теста: selected=favorite, allowed=allowed. Просмотр такого канала не подходит этой ограниченной кампании.

Исправление: применять ограничения кампании ко всем веткам выбора, включая прямую проверку подписок.

## 3. Высокий приоритет: запоздавший поиск включает стрим предыдущей игры

Место: renderer/js/pages/farming-page.js:4763–4795.

Начать «Другой стрим» в игре A; до ответа API перейти в игру B; завершить старый запрос. Продолжение метода использует список каналов A вместе с уже новым currentCategory. В тесте switchToStream получил old-game-channel при currentCategory = New game.

Исправление: фиксировать идентификатор сессии/категории до запроса и отбрасывать устаревший результат перед изменением плеера. Применить такую защиту ко всем асинхронным переключениям и остановке.

## 4. Высокий приоритет: уход со страницы отключает автоматику фарминга

Место: renderer/js/router.js:47,294–304; renderer/js/pages/farming-page.js:614,5774–5804.

При переходе с фарминга в настройки или статистику Router вызывает FarmingPage.destroy(). Тот удаляет таймеры проверки категории, прогресса дропов и зачёта, а также обработчик wt:player-dead. Плеер продолжает жить отдельно. Его сторож может чинить воспроизведение, но переключение на другой канал обрабатывает только уничтоженная страница. Автополучение готовых дропов вызывается из проверки прогресса этой же страницы.

Тест подтверждает удаление всех трёх проверочных таймеров и отмену обработчиков. Поиск по исходникам не обнаружил отдельного владельца этих задач вне страницы.

Исправление: перенести автоматику в контроллер сессии, живущий независимо от открытой вкладки.

## 5. Средний приоритет: выключенное автопереключение не соблюдается при смене игры

Место: renderer/js/pages/farming-page.js:4499–4531.

При autoSwitchStreams=false два ответа статистики с другой игрой всё равно приводят к switchToStream. Проверка настройки есть в onPlayerDead и onNoCredit, но отсутствует здесь. Дополнительно эта ветка выбирает канал прямо из выдачи, минуя pickPreferredStream и его ограничения кампании.

Результат теста при выключенной настройке: switches=1.

Исправление: единая проверка настройки и единый выбор подходящего канала для всех автоматических переключений.

## 6. Средний приоритет: старый ответ статистики меняет данные нового канала

Место: renderer/js/pages/farming-page.js:4477–4514.

Запрос статистики старого канала задерживается; пользователь переключается; приходит статистика нового канала, затем старого. Проверяется только существование страницы и DOM, но не соответствие ответа текущему каналу. В тесте число зрителей нового канала изменилось с 20 на 999, а ответ старого канала добавил ложное несовпадение игры. Оно может участвовать в последующем ненужном переключении.

Исправление: после await сверять канал и поколение запроса, сбрасывать счётчик несовпадений при смене канала.

## 7. Низкий приоритет: разные игры могут считаться одинаковыми

Место: renderer/js/pages/farming-page.js:4553–4558.

_gameMatchesCategory использует includes в обе стороны. Тест для World of Warcraft / Warcraft возвращает true. Это может пропустить смену игры, когда название одной категории является частью другой. У приложения также есть отдельная логика StreamPicker.isSameGame; правила сравнения сейчас неоднородны.

Исправление: по возможности сравнивать идентификаторы игр Twitch, а не подстроки названий.

## Повтор проверки

Штатный набор: `npm test`.

Дополнительные проверки: `node tests/audit-regressions.js`. На 1.0.22 воспроизводились шесть нарушений ожидаемого поведения. В 1.0.23 сценарии проходят, дополнены проверками обычного переключения и конкурирующих запросов и подключены к npm test.

Уведомления: запустить `node_modules/electron/dist/electron.exe tests/audit-notifications.cjs` из корня проекта в окружении без ELECTRON_RUN_AS_NODE. Тест показывает только свои уведомления, использует временный профиль, принудительно убирает оставшиеся окна и завершается с кодом 1 при воспроизведении зависания.

Порядок исправления: уведомления → независимый от вкладки контроллер фарминга → защита от устаревших запросов → единый выбор разрешённых каналов и соблюдение настроек.
